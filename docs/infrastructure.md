# Інфраструктура та Розгортання

Проєкт **Polytech League** використовує контейнеризацію для швидкого та надійного розгортання сервісів, а також містить інтегрований стек моніторингу.

## 🐳 Docker Compose

У корені проєкту знаходиться файл `docker-compose.yml`, який описує всі необхідні сервіси для повноцінної роботи платформи.

### Основні сервіси
1. **db (`postgres:17-alpine`)**: Основна реляційна база даних.
2. **redis (`redis:alpine`)**: In-memory база даних для кешування та підтримки SignalR.
3. **api**: .NET Backend (API).
4. **caddy**: Reverse Proxy сервер, який забезпечує маршрутизацію трафіку до API та автоматичну генерацію SSL сертифікатів (наприклад, перенаправляє `https://api.polytech-league.com` на внутрішній `api:8080`).

### Стек моніторингу (Observability)
Система включає повний набір інструментів від Grafana Labs для моніторингу метрик та логів:
- **prometheus**: Збір та зберігання метрик з сервісів (Time-series DB).
- **loki**: Система агрегації логів.
- **promtail**: Агент, який збирає логи з Docker контейнерів та відправляє їх у Loki.
- **grafana**: Інтерфейс (Dashboards) для візуалізації метрик (з Prometheus) та логів (з Loki). Доступний на порту `3000`.

## 🚀 Як запустити проєкт локально через Docker

1. Створіть файл `.env` у кореневій директорії (якщо його там немає) з необхідними змінними (користувач БД, паролі).
2. Виконайте команду:
   ```bash
   docker-compose up -d
   ```
   *Прапорець `-d` запускає контейнери у фоновому режимі.*

3. Зупинити всі сервіси:
   ```bash
   docker-compose down
   ```

## 🌍 Розгортання Frontend
Клієнтська частина (Frontend) налаштована на незалежне розгортання через платформу **Vercel**. 
У папці frontend та корені проєкту знаходяться файли `vercel.json` для правильної маршрутизації (Single Page Application) та налаштувань деплою.
Завдяки цьому оновлення UI відбувається швидко та не потребує зупинки бекенд сервісів.
